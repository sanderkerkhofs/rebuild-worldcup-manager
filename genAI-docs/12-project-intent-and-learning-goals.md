# 12 - Project Intent and Learning Goals

## Why this project exists

This project is a school assignment for learning fullstack JavaScript/TypeScript development.

The main goal is to demonstrate a complete and understandable fullstack CRUD application with:

- a clear backend
- a clear frontend
- a working database model
- role-based behavior
- documented API behavior

## Primary success criteria

This project is successful when it is:

- clear
- simple
- easy to explain in class
- easy to read and understand as a novice developer
- aligned with assignment requirements

## Scope and quality posture

- The tournament logic should be correct for demo and assignment use, but does not need to model every real-world football edge case.
- UI/UX should look clean and pleasant, but visual perfection is not the highest priority.
- The code should favor readability and structure over clever or highly optimized patterns.
- Avoid over-engineering and unnecessary abstractions.

## Development principles for this repository

1. Prefer straightforward code over advanced patterns.
2. Keep files and modules small and focused.
3. Add concise comments where logic may be hard for beginners.
4. Keep naming explicit and consistent.
5. Keep backend and frontend contracts typed and predictable.
6. Document important decisions in markdown.

## What to avoid

- Building features outside assignment scope.
- Adding complexity that does not improve learning outcomes.
- Introducing production-scale architecture patterns that reduce readability for beginners.
- Hiding core logic in deeply nested utility layers.

## Final note

This repository is a learning artifact first, and a realistic tournament simulator second.

If there is a conflict between architectural sophistication and beginner clarity, choose beginner clarity.
